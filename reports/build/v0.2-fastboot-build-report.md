Date: 2026-11-21
Package: `build/out/project-color-raven-v0.2-raven.zip` (2.0 GB, unzip verified)
Supersedes: v0.1 (symptom b: boots then reboots to fastboot) and the

## Root causes of symptom (b) — three independent boot killers

1. **fstab filesystem mismatch**
   LineageOS first-stage fstab (`fstab.gs101`, `fstab.gs101-fips`,
   `recovery.fstab` in vendor_boot) declared `ext4` for
   system/system_ext/product — but the ColorOS 17 donor images are
   **EROFS**. First-stage mount fails → kernel panics → reboot to
   fastboot.
   **Fix**: all 3 fstab files patched `ext4 → erofs` for
   system/system_ext/product; vendor stays ext4 (LineageOS image).

2. **system.img was root-style, not flat**
   Donor's raw system.img nests real content under `system/`
   (`system/system/bin/init`, ...), while root-level `bin`, `etc` are
   dangling symlinks to `/system/bin` etc. Flashing it raw would put
   files at `/system/system/...`; second-stage init could never find
   `/system/bin/init`.
   **Fix**: repacked FLAT from `donor/extracted/system/system/` with
   `mkfs.erofs --all-root` + 192 rewritten file-context entries
   (prefix `/system` stripped). Verified: 3834/3834 files extract,
   `/bin/init` (2,888,360 B) at image root, no nested `system/` dir,
   `fsck.erofs` exit 0.

3. **SELinux enforcing on unsigned mixed userspace**
   **Fix**: `androidboot.selinux=permissive` appended to vendor_boot
   bootconfig — same as timbostud/coloros17-bluejay RC1 (working
   ColorOS 17 port on Tensor G1).

## vendor_boot rebuild (mkbootimg round-trip)

- Original unpacked with `unpack_bootimg --format mkbootimg`
  (header v4, pagesize 0x800, dtb, 2 ramdisk fragments:
  platform + dlkm).
- Ramdisk00 repacked: fakeroot newc cpio → **legacy LZ4**
  (`lz4 -l -9`, magic `02214c18` matches original).
- Ramdisk contents: fstab patched (verified in round-trip),
  `init.environ.rc` added at ramdisk root (donor init imports it),
  `init → /system/bin/init` symlink preserved.
- Bootconfig: 3 lines incl. new `androidboot.selinux=permissive`.
- Rebuilt with system `mkbootimg` (vendor-4 syntax:
  `--vendor_boot`, named `--ramdisk_type` groups).
- Round-trip verified: unpack → fstab shows erofs for
  system/system_ext/product, bootconfig has permissive, init symlink +
  init.environ.rc present.
- Image: `build/tmp/vendor_boot_v02.img`, 30,048,256 B.

## Verification performed

- Every image SHA-256-verified against its source payload at extraction time
- Donor images byte-identical to donor OTA payload (payload-dumper hash-checked)
- Kernel decompressed (LZ4-legacy → 35.7 MB) and **EROFS built-in confirmed**
- Super capacity parsed: donor sizes fit with ≈ 3.8 GiB headroom
- flash-all.sh: `bash -n` clean; **zero wipe/erase/format tokens**; raven + unlocked gates; double confirmation
- Package zip: `unzip -t` integrity pass

## Safety

No flash/wipe/reboot commands were executed by the project against any device.
The package exists on disk only. Flashing is the owner's explicit action.

## Independent pre-flash safety audit (2026-11-20, second pass)

| Check | Result | Evidence |
|---|---|---|
| All images are raven/Pixel 6 Pro appropriate | **PASS** (with design note) | 8 hardware/boot-chain images hash-match the LineageOS raven payload; `vendor_boot` contains `raven`(6)/`gs101`(89) identifiers; donor `system/system_ext/product` are device-generic userspace by design (no OnePlus partition firmware inside) |
| No OnePlus hardware firmware/vendor/bootloader/modem flashed | **PASS** | 44 donor hardware partitions incl. xbl/tz/modem/dsp absent from the package; only donor userspace partitions included |
| A/B slot handling | **PASS** | All flashes go to the active slot (fastboot default); inactive slot retains previous ROM as automatic fallback; no `--skip-secondary` needed |
| fastboot vs fastbootd routing | **PASS (after fix)** | Logical (super) partitions: system/system_ext/product/vendor/vendor_dlkm — flashed in fastbootd; physical: boot/dtbo/vendor_boot/vbmeta×3 — flashed in bootloader mode; `vendor`/`vendor_dlkm` confirmed logical via super metadata parse |
| AVB/vbmeta configuration | **PASS** | All three vbmeta images flashed with `--disable-verity --disable-verification`; root vbmeta already flags=3; never re-lock (documented) |
| Dynamic partition sizes | **PASS** | Donor set sums 2.69 GiB vs group max ≈ 8.53 GiB (≈3.8 GiB headroom); fastbootd auto-resize |
| No userdata/metadata/persist formatting | **PASS** | Hazard grep on executable lines: zero erase/format/-w tokens; no such partition names appear; super_empty.img explicitly NOT flashed |
| Rollback instructions accurate | **FIXED then PASS** | README previously overstated data safety — corrected: script has no wipes, but cross-ROM swap may still require factory reset (FBE/keystore policy); backup mandatory; slot-fallback behavior documented |
| ZIP completeness | **PASS** | 60 entries: 11 images + super_empty + 2 scripts + README + checksums + 34 GCam addon files; every image hash re-verified from inside the zip |
| Flash order | **FIXED then PASS** | v1 script flashed boot chain before entering fastbootd → fastbootd would boot mixed (new vendor_boot + old vendor). v2: fastbootd (logical) first under consistent old chain → bootloader (never boots OS) → final reboot |

**Audit verdict: package cleared for owner-executed flashing.** Two defects
found and fixed (flash order, data-safety claim); zip re-packed and
integrity-re-tested. The project never flashes the device itself.
